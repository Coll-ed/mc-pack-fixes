# 农夫乐事煮锅顶面（水面）修复

## 结论：不是模组 bug，是资源包把锅口挖了个洞

**出问题的文件**：`resourcepacks\SPBR-Farmer's Delight_1.1.zip`

## 证据链（全部逐字节/逐像素核实，非推测）

### 1. 谁在管煮锅的外观
- 模组：`FarmersDelight-1.21.1-1.3.4.jar`
- 该资源包**同时替换了模型和贴图**：
  - `assets/farmersdelight/models/block/cooking_pot.json`（模型）
  - `assets/farmersdelight/textures/block/cooking_pot_top.png`（锅顶贴图）

### 2. 包里其实只动了「锅顶」这一张
逐条目哈希对比（原版模组 ↔ 资源包）：

| 贴图 | 结果 |
|---|---|
| `cooking_pot_side.png` | **逐字节相同** |
| `cooking_pot_parts.png` | **逐字节相同** |
| `cooking_pot_bottom.png` | **逐字节相同** |
| `cooking_pot_top.png` | **不同** ← 唯一真正改动 |

### 3. 洞在哪：`cooking_pot_top.png` 的 alpha 通道
16×16，只列第 2~13 行（锅顶 UV 采样区是 `[2,2,14,14]`）：

```
原版                                    资源包
..############..                        ..############..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..##........##..
..############..                        ..############..
```
- 原版：12×12 **全不透明** → 锅口是实心深灰
- 资源包：只有 2px 边框不透明，**中心 8×8 完全透明** → 锅口是个洞

资源包还给模型加了 **`"render_type": "minecraft:cutout"`**（cutout 会丢弃全透明像素，洞才真的透出来），
并补了一个「内壁」元素想让人看到锅内部。

### 4. 为什么那个洞「什么也挡不住」
- 农夫乐事**没有煮锅的方块实体渲染器**（模组类列表里无 renderer）
- blockstate 只有 `support`/`facing` 变体，**没有内部几何**（原版模型 4 个元素里没有内壁）
- 资源包补的内壁元素**没有 `up` 面**；从上方俯视时，它的四面竖直墙是侧视、`down` 面是背面 → 全被剔除

**所以从上方看就是直接看穿锅** —— 既没有水面，也没有锅内侧材质，只看到外面的地面与旁边方块。
这与你反馈的「水面消失、锅内侧材质也消失」完全对应。

### 5. 法线贴图不用动
包里的 `cooking_pot_top_n.png` 已核实 **16×16 全不透明（无洞）**，所以 PBR 法线不会重新引入问题。

## 修法

把资源包里的 `cooking_pot_top.png` **换回模组原版**（锅口恢复实心深灰）。

三种锅状态（直接放置 / 带提手 `cooking_pot_handle` / 放托盘 `cooking_pot_tray`）**共用这一张贴图**，
所以换一张贴图就把三种状态一次修好；包里的模型保留不动（内壁元素在实心锅顶下本来就不可见）。

## 交付与校验

| 项 | 值 |
|---|---|
| 被改文件 | `resourcepacks\SPBR-Farmer's Delight_1.1.zip` |
| 改动 | 仅 `assets/farmersdelight/textures/block/cooking_pot_top.png` 一个条目 |
| 修复后贴图 SHA(前16) | `5E3BA7C9AB08CA05` = 模组原版 |
| 备份 | `SPBR-Farmer's Delight_1.1.zip.bak`（545137 字节，SHA `1DD2DCF4A7C36065`） |
| 回滚 | `.\fix-fd-pot-top.ps1 rollback` |

**逐条目对比结果**：条目总数 505 → 505（无增无删）；
内容有差异的条目 **恰好 1 个**（就是目标贴图）；其余 **504 个逐字节相同**。

**生效方式**：进游戏按 `F3+T` 重载资源，或重启游戏。

## 附：为什么不能"就地"改 zip（实测踩坑）

`ZipFile` 的 Update 模式要求**独占**打开（`FileShare.None`）。这个 zip 被某个进程以
「**允许读写、但不允许删除**」的方式持有，于是：

| 操作 | 结果 |
|---|---|
| 只读打开 | ✅ |
| 共享读写打开 | ✅ |
| **`ZipFile.Open(Update)`** | ❌ 共享冲突 |
| 改名 / 移动原文件 | ❌ 共享冲突 |
| **覆写原文件** | ✅ |

所以脚本改成两阶段：**先在工作区生成修好的新 zip，再覆写原文件**（覆写只需写共享）。

另外两个小坑：
- 新条目的 zip 时间戳不能设为 Unix 0（1970），zip 合法下限是 **1980**；
- PowerShell 的 `-like`/`-notlike` 会把 `[` 当通配字符类，用 `[DateTimeOffset]` 做匹配会失败，改用 `.Contains()`。

## 复跑

```powershell
.\fix-fd-pot-top.ps1 status     # 只看现状
.\fix-fd-pot-top.ps1 apply      # 备份 + 换回原版贴图
.\fix-fd-pot-top.ps1 rollback   # 从备份还原
```

路径/文件名都在 `fix.config.psd1`（脚本不含写死路径）。
`fix.config.psd1` 与 `.ps1` 都必须是 **UTF-8 with BOM**。
