每一项都在 **Modrinth API** 上按 `loaders=["neoforge"] + game_versions=["1.21.1"]` 核实过（版本号、SHA1、字节数、前置、冲突声明）。

| # | 病灶 | 你已做的处置 | 模组还能帮什么 |
|---|---|---|---|

## 二、立即可装（5 个，全部核实）

### 1. ServerCore —— 服务端内存/性能大件
- 文件：`servercore-neoforge-1.5.19+1.21.1.jar`（1 462 674 字节）
- SHA1：`62ce692654e09271b5c55cbb3a1ef7606d067132`
- 链接：<https://modrinth.com/mod/servercore>
- **针对你**：295 模组包的 tick、实体激活范围、区块处理、方块实体检索的分配与耗时；自带"动态性能"（可按占用自动降模拟/视距）
- 环境：`server_only`（单人游戏的集成服务器照常生效）
- 冲突：无声明

### 2. ZFastNoise —— 你装的 byepregen **点名要求**它
- 文件：`zfastnoise-1.0.13+1.21.1+neoforge.jar`（39 526 字节）
- SHA1：`7b9f0b4d62a6e30505f8e64ebb58dfd2dc46c81e`
- 链接：<https://modrinth.com/mod/zfastnoise>
- **针对你**：`byepregen` 的元数据里明确写着 `noisium`/`noisiumed` **不兼容**、"**Please use ZFastNoise instead**"。你既没装 noisium 也没装 ZFastNoise ⇒ 预生成/探索时的世界生成没有这层加速。加速世界生成 = 同一段时间里更少的内存压迫
- 冲突声明：`NoisiumForked` / `Moonrise` / `AntiXray` —— **你三个都没装** ✓（已本机核对）

### 3. BadOptimizations —— 降低客户端的持续分配
- 文件：`BadOptimizations-2.4.1-1.21.1.jar`（283 566 字节）
- SHA1：`1461d8e46391efd32a3085150e86094c9f6f5c9d`
- 链接：<https://modrinth.com/mod/badoptimizations>
- **针对你**：光图/天空色缓存、实体与方块实体渲染器缓存、去掉冗余 FOV 计算 —— 直接减少"每帧都在分配"的量，也就是 GC 压力的源头之一
- 环境：`client_only`；自带配置，会自动把与某些模组冲突的项关掉

### 4. MoreCulling —— 剔除被遮挡的面（内存 + GPU）
- 文件：`moreculling-neoforge-1.21.1-1.0.10.jar`（335 699 字节）
- SHA1：`7e2d906031fdba883649eef6ef48a4dbdbb0f6cf`
- 链接：<https://modrinth.com/mod/moreculling>
- **针对你**：Create 的机械群、方块实体密集区（你这包 Create 全家桶 + 12 MB 的 createfood）；最新版还专门修了 Farmer's Delight 篮子的错误剔除
- **前置**：`Cloth Config API`（必需）—— **你已装 `cloth-config-15.0.140-neoforge.jar`** ✓
- 冲突：与 `particle_core` 的崩溃已在 1.0.1 修掉（你两个都会装，这条要记住）

### 5. Dynamic FPS —— 窗口失焦时停止渲染
- 文件：`dynamic-fps-3.11.4+minecraft-1.21.0-neoforge.jar`（220 193 字节）
- SHA1：`35b17e95b2b65930116ccc83e0cc358ac1bfcf9e`
- 链接：<https://modrinth.com/mod/dynamic-fps>
- **针对你**："**空余时间段**挂机跑区块"这个用法：窗口失焦/空闲时它把世界渲染停掉、帧率降到很低 ⇒ **挂机时几乎不再产生渲染侧内存与 GC 压力**（区块生成照常在跑）
- 环境：`client_only`；Cloth Config 可选（你已有）

## 三、需要你决策的一条：**Moonrise vs C2ME（互斥）**

**Moonrise**（Tuinity/Paper 系）优化：实体移动/碰撞/追踪、区块 tick/加载/生成/保存、方块与实体检索（寻路与 AI 高频使用）。

官方兼容表原文：

| 模组 | 状态 |
|---|---|
| Lithium | ✅ 兼容（自动关掉冲突部分） |
| FerriteCore | ✅ 兼容（自动关掉冲突部分） |
| **C2ME** | **❌ 不兼容** —— "C2ME is based around modifications to the chunk system, which Moonrise replaces wholesale." |

- 你**现在用 C2ME**（区块系统整体重写、异步 IO/序列化）→ 换来更快的区块加载
- 换 **Moonrise** → 换来更省的实体/区块 tick 与加载，但**失去 C2ME 的异步特性**；且 `ZFastNoise` 明确声明不兼容 Moonrise ⇒ 上面第 2 项就不能装
- **我的建议：先不动 C2ME**（你已装 `byepregen`，它的区块保存优化与 C2ME 是配套的）。若你想做 A/B 对比，我可以给你"卸 C2ME → 上 Moonrise"的完整步骤 + 回滚方案

## 五、安装顺序建议（一次一个，出问题好定位）

`ServerCore` → `ZFastNoise` → `BadOptimizations` → `MoreCulling` → `Dynamic FPS`

每加一个进一次游戏，确认日志没有新增 ERROR。你回传日志我可以做差分对比。

## 六、验收（你选的）

刚进游戏 / 玩一小时后，各记一次：
- 游戏内 **F3** 的堆占用
- 任务管理器里 **`javaw.exe` 的进程内存**

判据：两者都不再"只涨不降"。若堆平稳而进程仍涨 ⇒ 是 Voxy/原生那路（第 2 项 + 第 4 项继续压）；
若堆仍不降 ⇒ 回看 JVM 参数是否真的换成 ZGC 生效了（`logs/gc.log` 会给答案）。
